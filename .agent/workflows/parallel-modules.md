# 병렬 모듈 개발 워크플로우

이 워크플로우는 여러 독립적인 모듈을 동시에 개발할 때 사용합니다.

---

## ⚠️ 필수 사전 단계 (반드시 수행)

### Step 0: 정보 확인 및 질문

**시작 전 반드시 확인해야 할 정보:**

| 필수 정보 | 확인 여부 | 부족 시 질문 예시 |
|-----------|----------|------------------|
| 개발할 모듈 목록 | [ ] | "어떤 모듈들을 개발해야 하나요?" |
| 각 모듈의 목적/기능 | [ ] | "각 모듈의 주요 기능을 설명해 주세요" |
| 모듈 간 의존성 | [ ] | "모듈 간 의존 관계가 있나요?" |
| 타겟 플랫폼 | [ ] | "어떤 플랫폼/MCU를 사용하나요?" |
| 사용 언어/프레임워크 | [ ] | "C, Rust, 또는 다른 언어를 사용하나요?" |
| 코딩 컨벤션 | [ ] | "따라야 할 코딩 스타일이 있나요?" |

> [!IMPORTANT]
> **정보가 부족하면 절대 추측하지 말고 사용자에게 질문하세요!**
> 불명확한 정보로 개발을 시작하면 나중에 대규모 수정이 필요할 수 있습니다.

**질문 템플릿:**
```
병렬 모듈 개발을 시작하기 전에 몇 가지 확인이 필요합니다:

1. [누락된 정보 1]?
2. [누락된 정보 2]?
3. [누락된 정보 3]?

위 정보를 제공해 주시면 계획을 수립하겠습니다.
```

---

### Step 1: 계획 수립 (implementation_plan.md 작성)

> [!CAUTION]
> **계획 없이 코딩을 시작하지 마세요!**
> 반드시 `implementation_plan.md`를 작성하고 사용자 승인을 받은 후 진행합니다.

**계획서에 포함할 내용:**

```markdown
# 병렬 모듈 개발 계획

## 1. 개요
- 목적: [프로젝트 목적]
- 범위: [개발 범위]

## 2. 모듈 분석

| 모듈명 | 기능 | 의존성 | 예상 복잡도 | 담당 |
|--------|------|--------|------------|------|
| module_a | ... | 없음 | 중 | Agent A |
| module_b | ... | module_a | 고 | Agent B |

## 3. 개발 순서
1. 공통 인터페이스 정의
2. 독립 모듈 병렬 개발
3. 의존 모듈 순차 개발
4. 통합 테스트

## 4. 파일 구조
```
project/
├── src/
│   ├── module_a/
│   ├── module_b/
│   └── common/
└── tests/
```

## 5. 검증 계획
- 단위 테스트: ...
- 통합 테스트: ...
```

**사용자 승인 요청:**
```
계획서를 검토해 주세요. 수정이 필요하거나 승인해 주시면 개발을 시작하겠습니다.
```

---

## 실행 단계 (계획 승인 후)

### Step 2: 공통 인터페이스 정의
공통 헤더 파일 또는 trait/interface를 먼저 정의합니다:
- 타입 정의 (types.h 또는 types.rs)
- 에러 코드 정의
- 콜백 함수 시그니처

### Step 3: 태스크 그룹 생성
각 모듈을 별도의 태스크 섹션으로 분할하여 개발을 시작합니다.

```
[Task Group: 병렬 모듈 개발]
├── [Section 1: 모듈 A 개발]
│   ├── 헤더 파일 작성
│   ├── 소스 파일 구현
│   └── 단위 테스트 작성
├── [Section 2: 모듈 B 개발]
│   ├── 헤더 파일 작성
│   ├── 소스 파일 구현
│   └── 단위 테스트 작성
└── [Section 3: 통합]
    ├── 인터페이스 검증
    └── 통합 테스트
```

### Step 4: 병렬 개발 진행
각 태스크 섹션에서 해당 모듈을 독립적으로 개발합니다.

### Step 5: 통합 및 검증
// turbo
모든 모듈 개발 완료 후 통합 빌드 및 테스트를 수행합니다:
```bash
# C/C++ 프로젝트
make all && make test

# Rust 프로젝트
cargo build && cargo test
```
